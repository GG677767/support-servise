# Support Service

## 1. Описание проекта

Support Service — учебный проект для учета заявок службы технической поддержки.

Цель проекта — создать логичную структуру каталогов,
разделить данные по сущностям и подготовить основу
для дальнейшей разработки.

## 2. Назначение папок

### src/

Основная папка проекта.

### src/models/

Содержит основные сущности:

- tickets.csv — список 30 заявок.
- clients.csv — авторы заявок.
- assets.csv — оборудование.
- locations.csv — расположения и подразделения.

### src/dictionaries/

Содержит справочники:

- priorities.csv — приоритеты заявок.
- statuses.csv — статусы заявок.

### src/config/

Содержит настройки проекта.

- settings.md — правила хранения и обработки данных.

### tests/

Папка для будущих модульных тестов.

### data/raw/

Хранит описание исходных необработанных данных.

- source_records.md — информация о первоначальных 30 записях.

## 3. Правила обработки данных

- Даты приведены к формату YYYY-MM-DD.
- Каждая заявка имеет уникальный ID.
- Удалены лишние пробелы.
- Исправлено написание названий.
- Приоритеты приведены к единому формату.
- Для всех заявок установлен статус «новая», так как исходные статусы отсутствовали.

## 4. Таблица соответствия

Все 30 заявок находятся в файле src/models/tickets.csv.

Каждая запись является отдельной заявкой службы поддержки.

Дополнительные сведения распределены по файлам:

- Автор — clients.csv.
- Оборудование — assets.csv.
- Локация — locations.csv.
- Приоритет — priorities.csv.
- Статус — statuses.csv.

Все заявки находятся в одном основном файле,
поскольку относятся к одной сущности — заявкам.

## 5. Правила именования

- Названия папок пишутся маленькими буквами.
- Для разделения слов используется нижнее подчёркивание.
- Данные хранятся в формате CSV.
- Документация хранится в формате Markdown.
- Кодировка файлов — UTF-8.

## 6. Подготовка к A2 — Style Guide

Структура проекта позволяет в дальнейшем добавить единые правила оформления кода:

- именование переменных и функций;
- форматирование кода;
- оформление комментариев;
- организацию модулей.

## 7. Подготовка к A3 — Unit-тестирование

Папка tests подготовлена для будущих модульных тестов.

Планируемые проверки:

- уникальность идентификаторов;
- правильность дат;
- заполненность обязательных полей;
- корректность приоритетов;
- допустимые статусы.

## 8. Вывод

В результате создана структурированная основа
учебного проекта службы поддержки.

Обработаны 30 исходных записей, созданы отдельные
файлы сущностей и справочников, подготовлена документация.

Проект готов к дальнейшему изучению Style Guide
и Unit-тестирования.
